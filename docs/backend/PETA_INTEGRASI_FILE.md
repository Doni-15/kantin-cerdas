## Urutan integrasi dengan server backend

1. Gunakan [spesifikasi strict](SPESIFIKASI_BACKEND.md) dan [kamus data](KAMUS_DATA.md) sebagai kontrak pembangunan endpoint `/v1/*` di server backend.
2. Jalankan aplikasi dengan `--dart-define=API_BASE_URL=https://...` (dikonfigurasi melalui `AppEnvironment` di `app/lib/core/network/app_environment.dart`). Jangan pernah menyimpan secret server di dalam aplikasi klien.
3. Seluruh `RepositoryImpl` dan `ApiDataSource` untuk auth, katalog, checkout, pelacakan pesanan, pengajuan kantin, preferensi makanan, asisten, owner, admin, dan unggah media (`DioMediaUploadRepository`) telah terhubung melalui `buildProductionOverrides()` di `app/lib/app/production_overrides.dart`.
4. Pastikan server mengembalikan kode error JSON (`code` nonkosong sehingga `hasBackendErrorCode == true`) pada respons error bisnis (`400`/`401`/`403`/`404`/`409`/`422`/`429`) serta menyediakan keenam endpoint lookup `/v1/operations/*`.
5. Pertahankan jurnal lokal, penjagaan sesi/generasi, dan state UI; apabila kontrak API diubah, sinkronkan domain, model/mapper data, simulator, tes, dan dokumentasi.
6. Jalankan [pengujian](../../README.md#pengujian), tes kontrak/integrasi terhadap server staging, dan QA perangkat sebelum rilis.

## Dampak lintas file

- Kontrak/entity → adapter/controller/UI/simulator/tes/docs; schema jurnal berubah perlu migrasi, bukan hapus pending.
- Error → mapper/pesan/definitif-versus-unknown/retry policy (`hasBackendErrorCode`).
- Role/sesi → router/tujuan login/dialog/read session/controller/shell/storage namespace.
- Menu/harga/status → katalog/cart/checkout/order/receipt/invalidasi (`sharedDataRevisionProvider`).
- Pagination → query/bounds/cursor/reset/load-more/empty/error (`validatePaginationPage`).
